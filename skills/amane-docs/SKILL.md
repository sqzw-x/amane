# 文档与注释精简

遣词造句以 `docs/dev/writing.md` 为准; 项目用词见 `docs/dev/terms.md`.

## 开发文档

**范围**: 仅 `docs/dev/` 目录下的 markdown 文件. 不包括 AGENTS.md, `docs/user/` 目录下的用户文档以及源码注释.

开发文档只服务 Coding Agent, 不服务人类读者或终端用户. 它的唯一作用是**索引**: 用最少的阅读量把 Agent 送到一两个具体文件, 送到之后仍要读那些文件.
因此文档不求自足, 不承载实现细节; 一份文档的价值等于它替 Agent 省下的源码阅读量.

- 假设删除某句话, Agent 会不会因此多读文件或读错文件? 不会则删除
- 通常来说, 开发文档中不应出现过多符号名, 特别是局部性强的私有函数/内部方法名等; 而出现少量全局变量/配置字段/模块名/类名等则通常合理

## 判定

按三个去向落位:

- 源码本身已经说明的事实: 文档与注释都不写(代码自注释); 注意, 允许出于可读性等原因包含少量冗余注释, 如对长代码段进行划分总结
- 单个文件内部的原因与约束: 该文件的注释或 docstring.
- 跨模块的边界、顺序、契约、取舍: 开发文档 `docs/dev/`.

时效性: 文档只描述现在是什么、为什么, 以及仍生效的禁止事项. 禁止背景铺陈与迁移动机 (「从 A 改成 B」「以前是…」). 踩坑经验除外

## 精简流程

- 先精简再加: 新信息并入既有句子, 文档长度只允许持平或变短; 只有新增跨模块契约才允许增长.
- 同一内容只出现在一个文档; 交叉引用用相对链接, 指向源码用 `路径::符号`, 不写行号.
- 不新增文档; 确需新建时同步登记 `docs/dev/index.md`.
- 删除整篇文档时, 同步删除 `index.md` 的入口与其余文档中的引用.

## 注释

- 写该处的契约, 以及修改后受影响的边界.
- 同一约束只完整陈述一次, 其余位置引用.
- 措辞按 `docs/dev/writing.md` 与 `docs/dev/terms.md` 执行, 不在此复述其条款.
- 只描述当前状态. 沿革与未实现的计划不写入注释; 变更过程从 git 历史取得, 计划记入 `docs/roadmap.md` 或 Issue.
- 复述导入语句、复述文件名、复述调用方的实现描述属于无信息量, 一律删除.

## 验证

- 保留的每条结论都必须能在源码中找到依据.
- 精简不得改变语义: 约束不得说轻或说重.
- 删除后检查被删标题与文件的引用是否仍能解析.

## 范围

仅覆盖 `docs/dev/` 与源码注释. `docs/user/` 面向终端用户, 不适用
