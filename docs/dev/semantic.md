# 语义检索

封面与剧照的向量检索. 向量落 `{data_dir}/embeddings.db` (不进 Alembic, 删掉即重建), 端点契约见 [api.md](api.md)「`/metadata` 的语义参数」, 装载与排序实现在 `db/embeddings.py` / `semantic/ranking.py`.

## 检索契约

- 候选集先由主库筛选得到条目 id, 排名只在该集合内进行; 无筛选时扫全索引. 分数与筛选无关, 所以改筛选只改可见性.
- 一次查询只编码一次整句, 不按空格拆分. 图片分数与条目排名按 `(查询, 模型, 索引代次)` 缓存; 翻页、改筛选、换来源复用同一份排名, 只重做位图.
- 同分次序固定 `(分数降序, 条目 id 升序)`. 分页切片与 `total` 必须用同一份可见位图, 否则页长与总数会打架.
- `total` 与查询文本无关: 它是候选集里有该来源图片的条目数.

## 索引生命周期

- 索引常驻; 文本塔空闲释放不影响它. 只有模型 / 配置变化、语义关闭或显式释放才丢.
- 写入经 `EmbeddingStore` 提交后同步通知检索侧. 检索继续用旧索引, 后台单飞重装后原子替换; 新增与改图的可见性是最终一致, 期间可能仍按旧向量排名.
- 删除另有同步通道: 位图在删除请求返回前生效, 不等重装. 墓碑带写入代次, 切换索引时只应用比新索引新的那些 — `Metadata.id` 没有 AUTOINCREMENT, 删掉最大 id 后新条目会复用同一 id, 按 id 永久屏蔽会误杀新条目.
- 重装节流: 普通写入静默 5 s 后重装, 持续写入最多推迟 30 s; `build_index` 运行期间改为距上次装载满 10 分钟且行数增长 20%, 任务结束再强制补一次. 任务后段只改图不增行时会一直等到结束.
- 读盘失败不是空库: 重装失败保留旧索引并冷却后再试, 冷装载失败向请求报错. 把一边的读失败当成空索引会让检索静默失效到下一次写入.
- 所有写入必须经 store; 外部直接改 sidecar、多实例共享 `data_dir` 不产生通知, 需重启或显式释放索引.

## 装载

用独立只读连接在 `asyncio.to_thread` 里读一个快照: 不与写入共用 aiosqlite 连接, 快照内行数与行内容自洽. 整份装载是数秒到十几秒的量级 (100 万行约 3 GB, 大头是 SQLite 逐行取 BLOB), 所以冷启动的首个检索要等它, 重装则在后台进行. 不要给装载 SQL 加 `ORDER BY metadata_id` — 实测会建临时 B 树, 慢一个量级; 行序在装载后用下标重排成 `(条目 id, 来源)`, 矩阵不动.
