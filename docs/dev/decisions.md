# 维护者决策

> 记录维护者在 Issue 中作出、仍然生效的结论, 供 Issue 分诊与回答用户问题时直接引用, 不再重新论证.
> 每条给出触发情形、结论与处理, 括号内为出处 Issue; 链接指向回复用户时引用的用户文档.
> 维护者推翻某条结论时, 修改或删除该条, 不保留旧结论.

## 范围外

不实现. 回复时说明理由; 条目给出替代做法时附上替代做法, 否则不提供.

- **不准备内置的来源**: 用户请求新增的站点不在内置计划内时, 一律引导用户编写来源插件自行接入. (#425, #446, #460) [插件](../user/plugins.md)
- **读取本地 NFO 或复用本地图片**: 刮削不读取任何本地文件, 数据从来源单向流入数据库, 再经整理写出. 需要以本地数据为来源时, 把它实现为一个服务, 再写来源插件接入类型路由. (#154, #255) [插件](../user/plugins.md)
- **常规影视 (TMDB、豆瓣等) 的刮削**: 暂不考虑. 同类工具已经与媒体服务器结合良好; 数据结构耦合成人内容; 大流量来源的反爬维护成本高. (#425)
- **共享片库 / 众包元数据**: 不实现, 法律风险与维护成本无人承担. (#615)
- **海报一律从封面裁切, 不采用来源提供的海报**: 不采用. 部分片商的海报不是封面的一半, 一律裁切会破坏这些海报. (#397)

## 按设计如此

用户报为缺陷的现象是预期行为. 改判为 `kind:question`, 说明机制与做法; 用户要求改变该行为时按 `kind:enhancement` 保留, 引用本条作为既有结论.

- **刮削或编辑后, 磁盘上的文件名、目录、NFO 与图片没有变化**: 刮削与编辑只写入数据库, 写出文件由整理执行. (#433, #634) [整理](../user/organize.md)
- **整理时目标路径被占用, 文件被跳过**: 目标路径被其它文件占用时不覆盖、不改名、不移动, 记为冲突, 也不追加后缀消除冲突; 由用户移走占用的文件或修改路径模板后重新整理. 同一影片自身的 NFO 与图片每次整理都会覆盖, 不属于冲突. (#433, #315) [路径冲突](../user/organize.md#conflicts)
- **清理不删除仍有视频的目录**: 只有同目录、各上级与各子目录都没有视频文件时, 该目录才算残留. 让视频文件与其父目录使用同一命名模板, 模板变化后旧目录即成为残留. (#476)
- **整理没有「只处理新增文件」的模式**: 每次按当前模板重新处理范围内的全部已刮削文件, 不产生重复文件; 部分处理用文件表勾选后批量整理, 或在提交任务时填写子路径. [整理](../user/organize.md)
- **修改字段优先级或字段排除后, 已有影片不变**: 重新刮削即按新设置重算字段, 不需要强制刮削; 新启用的来源会自动补充. (#514) [字段优先级](../user/scraping.md#field-priority)
- **合并影片后来源链接没有合并**: 来源与字段按当前类型路由在重新刮削时聚合, 无条件合并的来源在重新刮削后也会消失. 合并对话框提供「合并后重新刮削」. (#644)
- **再次整理后 `-C` / `-U` 等标记消失**: 标记每次从当前路径重新识别, 只认规范写法; 路径模板的值映射只改变输出文字, 映射结果不会被再次识别. 需要保留标记时让模板输出规范值. (#628, #524) [文件标记](../user/organize.md#file-markers)
- **同一番号前缀同时属于有码与无码片商**: 规则无法区分, 番号相同时只能人工比对; 用「指定番号刮削」填写正确的番号与内容类型. (#438)
- **不内置播放器**: 播放面板由播放源插件提供. 播放本地视频推荐示例插件 [amane-local-file](https://github.com/sqzw-x/amane-local-file): 把媒体库中已索引的文件按原始字节流交给浏览器, 不做解码、转码与封装转换, 能否播放取决于浏览器 (`.mkv` 通常不能); 该插件只接受缺陷报告. 需要转码与完整串流时使用 Emby / Jellyfin. (#520) [播放](../user/playback.md)

## 不归项目负责

问题由用户环境或上游决定. 改判为 `kind:question`, 说明责任归属与可行做法, 不追问复现信息.

- **挂载 SMB / WebDAV / NFS 等远程目录**: 由用户在系统层挂载, 再把挂载路径添加为媒体库; 挂载之后使用中的问题按缺陷处理. (#427)
- **云盘挂载 (CD2 等) 上硬链接失败, 报 `WinError 1` / `WinError 17`**: 该文件系统不支持硬链接. 改用链接路径模板创建库外的 STRM 或符号链接, 或改用移动 / 复制. (#199) [链接与 STRM](../user/organize.md#links)
- **FlareSolverr 无法通过 Cloudflare 挑战**: 上游能力所限, 项目无法修复; 可以更换浏览器后端, 桌面版可使用 BrowserSkill. (#550) [浏览器渲染](../user/network.md#browser)
- **Docker 拉取镜像失败**: 网络环境问题, 为 `ghcr.io` 配置镜像源. (#614)

## 既有能力可达成

以下需求不需要新增功能. 改判为 `kind:question`, 写出具体做法.

- **某些字段优先采用指定站点的值** (标题取日文原名、图片取高清来源等): 设置该字段的站点顺序. (#533, #446) [字段优先级](../user/scraping.md#field-priority)
- **整理时视频保持原位** (保种、保留原有目录结构): 视频路径模板设为 `{raw_relpath}`, 整理方式保持「移动」, 目标与源路径相同, 磁盘上没有搬迁; 附属资源模板保持默认时 NFO、图片与字幕写在视频旁. 路径段末尾的 `.` 与空格仍会被规范化. 原地整理同时重命名视频由 #629 跟踪. (#506, #667) [占位符](../user/organize.md#placeholders)
- **数据目录持续增大**: 「清理」任务删除失效的文件索引与无影片引用的资源文件, 可设为定时任务. (#607) [任务](../user/tasks.md)
- **预告片等大文件下载失败或缺失**: 分块下载中任一分块失败即整体失败, 调整分块下载参数. (#561) [分块下载](../user/network.md#chunked)
- **修改 `desktop.env` 等配置文件后不生效**: 行首的 `#` 表示注释, 删除后该行才生效. (#581, #582) [桌面设置文件](../user/clients.md#desktop-env)

## 已定方向

维护者已表态的方向. 同类新请求按重复处理, 指向括号内的跟踪 Issue; 不给出与该方向冲突的建议.

- **NFO 内容自定义**: 已排期. 当前 NFO 内容固定, 标题为「番号 + 空格 + 标题」, 标题已带番号前缀时不再重复; 需要不同的显示标题时修改影片的标题字段. (#102) [NFO](../user/media-server.md#nfo)
- **配置预设**: 计划实现, 以功能或逻辑单元为单位 (LLM API、优先级规则等), 不以整份配置为单位. (#422)
- **同一番号存在多个条目**: 已立项. (#556)
- **新出现的破解来源标识** (LTX 等): 并入「破解」的识别关键词, 不新增独立标签或类型 —— 这类标识随模型更替而变化. (#583)
- **字幕刮削**: 优先级低, 近期不实现. (#73)
- **片库高级筛选**: 筛选面板未覆盖的条件交给智能体, 由其生成查询预设. (#165) [智能体](../user/agent.md)
- **桌面版的 Patchright 后端**: 当前不支持, 属实现限制; 改为调用本机浏览器的适配优先级低. (#566) [浏览器渲染](../user/network.md#browser)
