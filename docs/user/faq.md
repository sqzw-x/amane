# 常见问题

本页按症状列出常见问题的原因与处理方法, 适用于所有部署方式. 每条只给出排查要点, 完整说明见链接的专题页.

## 定位与用法

??? question "没有本地视频文件时如何使用"
    直接提交番号: 在「任务 → 提交任务」中填写番号, 或用批量刮削、订阅与智能体提交, 刮削结果即可在片库中浏览与修订. 媒体库是从本地文件名识别番号的另一种来源, 整理与播放按需启用. 见 [安装与快速开始](index.md#quickstart).

??? question "刮削完成后, 文件名、目录和 NFO 都没有变化"
    刮削只把站点结果写入数据库与资源目录, 不修改媒体库中的文件, 也不写出 NFO; 文件操作由「整理」执行. 在媒体库页点击「整理落盘」、在文件表勾选后「批量整理」, 或开启媒体库的「自动整理」, 才会按路径模板放置视频并写出 NFO 与图片. 不涉及本地文件时不必整理, 片库中的元数据与图片照常可用. 见 [整理与路径模板](organize.md).

??? question "片库与媒体库有什么区别"
    片库列出影片, 即按番号刮削得到的元数据条目; 媒体库是磁盘上的目录与其中的视频, 是可选的一种番号来源. 一部影片可以关联零个或多个媒体文件; 扫描媒体库把新文件入库并刮削其中的待处理项, 整理另行触发. 见 [安装与快速开始](index.md) 与 [媒体库](libraries.md).

??? question "Amane 能替代 Emby / Jellyfin 吗"
    两者分工互补. Emby / Jellyfin 管理媒体文件并负责播放与串流; Amane 负责多源刮削与元数据管理, 需要时把结果以 NFO 与图片写到视频旁, 供媒体服务器读取. 见 [对接 Emby / Jellyfin](media-server.md).

## 登录与访问

??? question "忘记或找不到 API Token"
    API Token 在首次启动时自动生成, 保存在数据目录的 `token` 文件中, 之后每次启动复用同一个值. 取得方式:

    | 部署方式 | 取得方式 |
    |----------|----------|
    | 桌面版 | 点击菜单栏 / 托盘图标 → 「复制 API Token」 |
    | Docker | `docker logs amane` 查看启动日志, 或读取数据目录 (默认挂载为 `./data`) 中的 `token` 文件 |
    | 源码运行 | 查看终端中的启动日志, 或读取数据目录中的 `token` 文件 |

    设置了环境变量 `AMANE_TOKEN` 时, Token 即该变量的值, 不读取 `token` 文件. 删除 `token` 文件并重启服务会生成新的 Token. 详见 [安装与快速开始](index.md) 与 [配置参考](configuration.md).

??? question "登录后仍然提示 401 或「Token 无效」"
    除健康检查等少数接口外, 所有接口都要求有效的 API Token. 浏览器登录后以 Cookie 保存 Token, 服务端的 Token 变化后, 已保存的 Cookie 失效, 接口返回 401 (`缺少或无效的 API token.`).

    常见原因:

    - 删除了 `token` 文件或更换了数据目录, 服务端生成了新的 Token.
    - 修改了 `AMANE_TOKEN` 的值.
    - 粘贴的 Token 带有多余字符, 或来自另一个 Amane 实例.

    处理方法: 按上一条重新取得当前 Token, 在登录页重新输入. 命令行工具与外部智能体使用 `Authorization: Bearer <Token>` 请求头, 不使用 Cookie.

??? question "桌面版如何从其它设备访问"
    桌面版默认只监听 `127.0.0.1:18000`, 只接受本机连接. 点击菜单中的「打开设置文件」, 在 `desktop.env` 中写入 `AMANE_HOST=0.0.0.0`, 需要修改端口时同时写入 `AMANE_PORT`, 然后点击「重启服务器」, 再从其它设备访问 `http://<主机地址>:<端口>`. 系统可能询问是否允许传入连接, 需要允许. 详见 [客户端](clients.md#desktop-env).

## 刮削

??? question "刮削不到元数据, 或字段不全"
    先打开对应的刮削任务, 查看各站点的结果与失败原因. 常见原因:

    - **番号识别错误**: 文件名中没有可识别的番号时, Amane 以清理后的文件名作为番号, 类型记为欧美, 刮削通常失败. 在媒体库页使用「指定番号刮削」填写正确的番号与内容类型.
    - **类型路由中没有合适的站点**: 每种内容类型只请求其类型路由中的站点, 列表为空时该类型的刮削直接失败.
    - **字段优先级与字段排除**: 字段排除使该字段不采用指定站点的值; 可选站点过少时字段可能为空.
    - **站点不可达**: 见下一条.
    - **缓存**: 普通「刮削」复用已缓存的站点数据; 站点数据有更新时, 使用「强制刮削」重新获取全部来源.

    详见 [刮削](scraping.md).

??? question "某个站点被拦截、超时或需要登录"
    在侧栏「运行 → 网络检测」查看每个来源是否可访问以及失败原因, 再按原因处理:

    | 原因 | 处理方法 |
    |------|----------|
    | 网络不可达、超时、地区限制、IP 被封 | 在「设置 → 网络」设置代理; 也可以在「设置 → 影片刮削 → 站点配置」中为单个站点设置站点代理或自定义域名 |
    | 请求过于频繁 | 降低该站点或该域名的速率限制; 容易触发限制的站点可降到每秒 0.5 次以下 |
    | Cloudflare 挑战页 | 在「设置 → 网络」配置浏览器渲染, 并在站点配置中设置该站点的浏览器策略 |
    | 需要登录 | 在该站点的站点配置中填写登录后的 Cookie 或 API Token |
    | 请求被站点拒绝 | 多为出口 IP 被拒绝, 更换代理出口后重试 |

    结论为「缺少凭据」的来源在刮削时同样会被跳过. 桌面版与 Docker 没有内置浏览器, 浏览器渲染只能使用 Solver 服务 (FlareSolverr 等). 详见 [网络与站点访问](network.md).

??? question "任务显示成功, 但某个站点没有取到数据"
    只要有一个站点返回结果, 刮削任务即视为成功; 单个来源失败不会使任务失败. 各站点的成功、缓存与失败及其原因列在任务详情的「任务结果」中, 演员刮削同理. 网络检测只确认站点入口能否访问, 站点结果才是刮削时的真实结论. 详见 [任务与定时任务](tasks.md) 与 [结论解读](network.md#reasons).

??? question "番号识别错误, 或站点提示找不到该番号"
    扫描与文件刮削从文件名识别番号, 文件名识别不到时依次尝试各级父目录名, 内容类型由番号形态推断. 识别错误时在媒体库详情页的文件表中对该文件使用「指定番号刮削」, 填写正确的番号与内容类型; 影片的类型只在创建时确定, 之后不能修改. 也可以改文件名后重新扫描, 或在「任务 → 提交任务」中按番号直接刮削. 识别规则见 [番号与类型识别](scraping.md#identify).

??? question "无码影片取不到 javdb 的数据"
    javdb 对无码影片与无码演员档案需要登录: 未配置 Cookie 时, 这两类内容的结果为「需要登录」, 有码内容与搜索页不受影响. 在「设置 → 影片刮削 → 站点配置 → javdb」中按名称逐项填入浏览器的登录 Cookie, Cookie 过期后重新填写. 无码内容也可以优先使用 avsox. 详见 [站点登录与凭据](network.md#credentials).

??? question "不同站点需要不同地区的节点"
    站点可以单独设置代理或直连: 在「设置 → 影片刮削 → 站点配置」中关闭某个站点的「使用代理」使其直连, 或填写「站点代理」使用该地址. 站点设置只作用于该站点自身的域名, 图片 CDN 等其它域名仍使用全局代理. 详见 [按站点代理](network.md#site-proxy).

??? question "演员的三围、身高或生日缺失"
    演员资料按「演员资料优先级」逐项取第一个非空值, 各来源覆盖的字段不同: minnano 提供身高与三围, wikipedia 提供简介与信息框中的部分身材信息. 先在演员详情查看「刮削来源快照」, 再到演员刮削任务的结果中确认哪些来源失败. minnano 的检索页受人机验证保护, 桌面版与 Docker 需要 Solver 服务. 详见 [演员刮削](scraping.md#actor-scraping).

??? question "演员没有头像"
    头像来自 gfriends 与各资料来源附带的图片. 演员性别为「未知」时不请求 gfriends, 在演员编辑界面设置性别后重新刮削. minnano 的图片受挑战保护, 需要 Solver 服务; 无码演员在 javdb 的头像需要 Cookie. 详见 [演员刮削](scraping.md#actor-scraping).

??? question "男演员排在第一位, 或整理到错误的演员目录"
    `{actor}` 取聚合后演员列表的第一位, 顺序由「字段优先级 → 演员」决定; javdb 是同时写入男女演员的来源, 把它排在演员字段的后面即可. 也可以在影片编辑表单中调整演员顺序, 或改用 `{actress}` 取第一位女演员. 详见 [占位符](organize.md#placeholders).

??? question "同一演员出现多个条目"
    演员页的列表视图支持合并: 勾选要并入的条目, 点击目标行的合并图标, 目标保留, 被并入的名字成为别名. 别名只增不减, 需要固定时锁定「别名」字段. 详见 [演员](browse.md#actors).

??? question "LLM 翻译不生效"
    翻译在刮削时执行, 只作用于之后刮削的影片, 不会自动处理已入库的影片. 逐项核对:

    1. 「设置 → LLM 翻译」中已开启「启用 LLM 翻译」, 且填写了「API 密钥」与「模型」. 没有 API 密钥时翻译功能不启用. 翻译与智能体的凭据、模型分别配置, 互不影响; 智能体可用的密钥不代表翻译可用, 反之亦然.
    2. 目标字段在「翻译字段」中. 当前只翻译标题与剧情; 标签需要翻译时, 用智能体批量修改.
    3. 目标语言取自「设置 → 影片刮削」的「字段语言偏好」. 原文已经是目标语言时不翻译; 中文简繁之间直接转换, 不调用 LLM.
    4. 翻译请求失败时保留原文, 刮削不会因此失败. 在「运行 → 日志」中搜索翻译失败的记录.

    译文按原文缓存: 原文不变时, 重新刮削复用已有译文. 更换模型后需要重新翻译时, 删除数据目录中的 `translations.db`; 修改提示词后旧译文自动失效, 不需要删除. 详见 [刮削](scraping.md#llm).

## 部署与运行

??? question "端口被占用, 或需要修改端口"
    端口被占用时服务启动失败, 日志中有地址无法绑定的错误.

    === "Docker"

        修改 `compose.yaml` 中 `ports` 的宿主机端口, 如 `"18080:8000"`, 容器内端口保持 `8000`: 自带的健康检查请求的是容器内的 `8000` 端口.

    === "桌面版"

        桌面版默认端口为 `18000`. 点击菜单中的「打开设置文件」, 在 `desktop.env` 中写入 `AMANE_PORT=<端口>`, 然后点击「重启服务器」.

    === "源码运行"

        设置环境变量 `AMANE_PORT` 后重新启动服务, 默认端口为 `8000`.

    监听地址由 `AMANE_HOST` 控制, 见 [配置参考](configuration.md) 与 [客户端](clients.md).

??? question "桌面版服务启动失败"
    服务启动失败时, 菜单栏 / 托盘菜单的状态行显示「启动失败」与原因 (服务输出的最后一条错误), 桌面程序在等待后自动重试. 状态行显示「未连接」时, 表示服务尚未就绪或已退出.

    查看完整日志:

    | 系统 | 日志目录 |
    |------|----------|
    | macOS | `~/Library/Application Support/Amane/logs/` |
    | Windows | `%LOCALAPPDATA%\Amane\logs\` |

    `app.log` 是服务日志. 在 `desktop.env` 中修改了 `AMANE_DATA_DIR` 或 `AMANE_LOG_DIR` 时, 日志位于对应目录. 常见原因是端口被占用 (见上一条) 与 `desktop.env` 中的取值不合法; `desktop.env` 中无法识别的键只提示一次并被忽略. 详见 [客户端](clients.md).

??? question "Windows 上页面空白, 或提示模块脚本的 MIME 类型错误"
    系统注册表中 `.js`、`.mjs`、`.css`、`.svg`、`.html` 的 Content Type 被其它程序改写后, 浏览器拒绝加载页面脚本, 页面显示空白, 控制台提示 `Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of "text/plain"`.

    以管理员权限打开命令提示符, 删除用户级与系统级注册表中这些扩展名的 Content Type 值:

    ```cmd
    for %E in (.js .mjs .css .svg .html) do reg delete "HKCU\Software\Classes\%E" /v "Content Type" /f
    for %E in (.js .mjs .css .svg .html) do reg delete "HKLM\SOFTWARE\Classes\%E" /v "Content Type" /f
    ```

    命令没有输出即为删除成功. 重启 Amane 后, 在浏览器中强制刷新.

??? question "macOS 应用打不开, 或提示「已损坏」"
    应用没有代码签名, 从网络下载后会被 Gatekeeper 拦截. 执行以下命令后重新打开:

    ```bash
    sudo xattr -d com.apple.quarantine /Applications/Amane.app
    ```

    每次覆盖更新后都需要重新执行. 系统要求为 macOS 13 及以上, 更早的系统不在支持范围内, 需要时可以从源码安装并自行解决依赖. 详见 [安装与快速开始](index.md#install).

??? question "数据迁移与备份"
    Amane 的全部状态都在数据目录 (`AMANE_DATA_DIR`) 中:

    | 内容 | 位置 |
    |------|------|
    | 数据库 | `amane.db` |
    | 应用配置 | `config.toml` |
    | API Token 与图片 Token | `token`、`image_token` |
    | 已下载的图片与预告片 | `resources/` |
    | 插件与插件数据 | `plugins/` |
    | 翻译缓存 | `translations.db` (可以删除, 自动重建) |
    | 日志与任务记录 | `logs/` (Docker 与桌面版的默认位置) |

    数据目录的默认位置: Docker 为挂载到 `/data` 的目录; macOS 为 `~/Library/Application Support/Amane`; Windows 为 `%LOCALAPPDATA%\Amane`.

    备份与迁移:

    1. 停止 Amane 服务. 服务运行时数据库的部分改动尚未写入 `amane.db`, 此时复制会丢失这些数据.
    2. 复制整个数据目录到目标位置.
    3. 在新环境中把 `AMANE_DATA_DIR` 指向该目录后启动.

    媒体库保存的是绝对路径. 新环境中媒体目录的路径不同时 (如在 Docker 与桌面版之间迁移), 需要在媒体库页修改路径, 或保持相同的挂载路径. 修改 `AMANE_DATA_DIR` 不会迁移已有数据. 升级时数据库在启动阶段自动迁移, 迁移前写入备份, 详见 [配置参考](configuration.md).

## 路径与权限 (媒体库)

??? question "媒体库路径被拒绝 (403 或「不在允许的安全目录内」)"
    Amane 只允许访问安全目录内的路径, 媒体库路径、文件浏览器与插件安装路径都受此约束. 安全目录的来源:

    - 设置了 `AMANE_SAFE_DIRS` 时, 取该变量列出的目录 (逗号分隔), 不存在的目录被忽略.
    - 未设置时, 取服务启动时已有媒体库的路径. 没有任何媒体库时安全目录为空, 文件浏览器报「尚未配置安全目录」.
    - `AMANE_SAFE_DIRS=ALLOW_ALL` 关闭该限制. 桌面版默认如此.

    | 现象 | 处理方法 |
    |------|----------|
    | `路径 ... 不在允许的安全目录内` (403) | 把该路径的上级目录加入 `AMANE_SAFE_DIRS`, 然后重启服务 |
    | `尚未配置安全目录, 无法校验路径` | 设置 `AMANE_SAFE_DIRS`, 然后重启服务 |
    | `路径不存在: ...` (404) | Docker 中填写的必须是容器内路径 (如 `/media`), 并确认该目录已挂载 |

    `AMANE_SAFE_DIRS` 是环境变量, 修改后必须重启服务. 详见 [配置参考](configuration.md).

??? question "Docker 挂载目录无法写入, 或生成的文件属主是 root"
    官方 `compose.yaml` 以 `user: "${UID:-1000}:${GID:-1000}"` 运行容器. 多数 shell 不会把 `UID` / `GID` 导出为环境变量, 此时容器以 `1000:1000` 运行. 宿主机用户的 UID 不是 1000 时, 容器无法写入数据目录与媒体目录, 整理、写入 NFO 与图片均会失败.

    处理方法:

    1. 在宿主机执行 `id -u` 与 `id -g` 取得当前用户的 UID 与 GID.
    2. 在 `compose.yaml` 同目录的 `.env` 文件中写入 `UID=<值>` 与 `GID=<值>`, 或直接修改 `user:` 一行.
    3. 确认该用户对 `./data` 与各媒体目录具有读写权限, 然后重新创建容器.

## 文件发现与扫描 (媒体库)

??? question "NAS / NFS / SMB / Docker Desktop / WSL2 下文件监控不触发"
    文件监控依赖操作系统的文件事件. 网络文件系统、Docker Desktop 的目录共享与 WSL2 访问 Windows 磁盘时, 这些事件通常不会传递到 Amane, 新文件因此不会自动入库.

    处理方法:

    1. 在「设置 → 文件监控」开启「轮询模式」, 然后**重启服务**. 该设置只在服务启动时读取.
    2. 确认媒体库的「自动化」不是「关闭」.

    轮询模式只作用于文件发现方式为「本地文件」的媒体库. CloudDrive2 挂载的媒体库使用「CD2 webhook」, 不依赖文件事件. 无法使用监控时, 可以在媒体库页手动扫描, 或用定时任务周期执行扫描. 详见 [媒体库](libraries.md) 与 [任务与定时任务](tasks.md).

??? question "扫描不到文件"
    按顺序核对媒体库与「设置 → 文件监控」的设置:

    - 媒体库设置了「匹配模式」时, 只有匹配这些通配符的文件入库, 媒体扩展名不再生效; 未设置时, 文件扩展名必须在「媒体扩展名」内. 修改「媒体扩展名」后须重启服务.
    - 文件位于子目录, 而媒体库未开启「递归」.
    - 文件名命中「预告片文件名正则」, 被视为预告片跳过.
    - 文件名命中「文件黑名单正则」, 或小于「最小视频大小」: 这类文件是无效文件, 不入库, 在「清理」中列为候选.
    - 路径位于 `.amane_trash` 内: 任意深度的该目录都被忽略.
    - CloudDrive2 挂载的媒体库未填写「CloudDrive 路径」, webhook 事件无法对应到媒体库.

    详见 [媒体库](libraries.md).

??? question "扫描的文件数多于片库中的影片数"
    同一番号的多个分片或重复文件归属同一部影片, 计为多条关联文件, 而片库按影片计数, 因此片库数量可能少于文件数量. 在列表视图按「关联文件」排序, 或筛选「关联文件 → 有文件」核对. 详见 [片库与浏览](browse.md).

## 整理与图片 (媒体库)

??? question "整理后源目录仍然存在"
    源文件是否离开原位置取决于媒体库的「整理方式」:

    - **移动**: 视频移动至目标路径, 本次腾空的目录被删除 (库根与 `.amane_trash` 除外). 目录内仍有其它文件 (如旧的 NFO、图片、无关文件) 时不会被删除.
    - **复制**、**硬链接**、**符号链接**: 源文件保持原位, 源目录保留.

    残留的附属文件与空目录可以在媒体库的「清理」中扫描并确认删除. 详见 [整理与路径模板](organize.md) 与 [媒体库](libraries.md).

??? question "整理时出现冲突, 文件被跳过"
    目标路径已有其它文件时, Amane 不覆盖、不改名、不移动该文件, 记为冲突, 文件留在源路径. 任务详情的「未处理的冲突」列出源路径与被占用的目标路径; 字幕的目标路径被占用时同样记为冲突.

    处理方法: 检查目标路径上的文件, 删除或移走不需要的那一份, 或修改路径模板使目标不再重复, 然后重新整理. 源与目标已是同一文件 (如硬链接) 时不算冲突. 尚未刮削的文件计入「跳过」, 不计入冲突. 详见 [整理与路径模板](organize.md).

??? question "能否只整理新增或部分文件"
    整理每次都在范围内按当前模板重新处理全部已刮削文件, 没有「只处理新增文件」的模式; 已整理的文件再次整理不会产生重复文件. 只处理部分文件时, 在媒体库文件表勾选后「批量整理」, 或在「任务 → 提交任务」的整理中填写子路径. 详见 [触发方式](organize.md).

??? question "整理到库外, 或提示链接路径错误"
    库内整理应使用「移动」: 复制、硬链接与符号链接在目标仍位于库内时保留源文件, 再次扫描会把源路径再入库为另一个文件. 需要库外链接 (视频在网盘、元数据在本地) 时, 使用「链接路径模板」创建库外的 STRM 或符号链接; 链接路径必须是库外的绝对路径, Docker 中还须位于 `AMANE_SAFE_DIRS` 内.

    硬链接要求源与目标在同一文件系统, 云盘挂载不支持硬链接, 报 `WinError 17` 或 `WinError 1`. 链接已存在且内容一致时不改写. 详见 [链接与 STRM](organize.md#links).

??? question "第二次整理后 -C / -U 标记消失"
    中字、破解、分集与分辨率标记每次整理时都从当前路径重新识别, 只认规范写法: 中字 `-C` / `-UC`, 破解 `破解` / `CRACKED` / `-U`, 流出 `流出` / `LEAKED`, 无码 `无码` / `UNCENSORED`. 路径模板的值映射只改变输出文字, 映射得到的自定义文字不会被再次识别; 需要标记长期保留时, 让模板输出上述规范值. 见 [文件标记](organize.md#file-markers).

??? question "字幕文件跟着别的视频一起整理"
    视频同目录的字幕随视频一同整理. 字幕文件名能解析出番号时按番号配对; 解析不出时只按分集标记配对, 无分集标记的字幕归入无分集或 CD1 的视频. 平铺目录中多部影片共用一个目录时, 字幕会归到错误的影片, 应为每部影片保留独立目录, 或在字幕文件名中写入番号. 详见 [字幕](organize.md#subtitles).

??? question "图片缺失, 或水印没有出现"
    图片在两个时机下载到 Amane 的资源目录: 刮削时下载「设置 → 影片刮削 → 刮削时下载」中勾选的类型; 封面、海报与剧照未勾选时, 在访问影片详情页时下载. 整理时, 媒体库「整理时复制」中勾选的类型被复制到库路径, 资源目录中缺少的图片在整理时现场下载.

    | 现象 | 原因与处理 |
    |------|------------|
    | 库路径中没有某类图片 | 该类型未在媒体库的「整理时复制」中勾选, 或所有来源都没有该图片 |
    | 没有海报 | 来源未提供海报时, 开启「裁切海报」后从封面裁切生成 |
    | 库路径中的图片没有水印 | 水印只在整理时绘制到库路径的封面与海报上. 开启「设置 → 水印」的「启用水印」后, 重新整理已有影片 |
    | 片库中的角标与「启用水印」不一致 | 片库页面的角标由界面绘制, 不受「启用水印」影响, 也不代表库路径图片上已有水印 |

    自定义水印图片放在数据目录的 `watermarks/` 中. 详见 [整理与路径模板](organize.md#watermark) 与 [配置参考](configuration.md).

## 对接媒体服务器

??? question "Emby / Jellyfin 无法显示图片"
    先区分图片的来源:

    - **库路径中的本地图片**: 确认媒体库已整理, 「整理时复制」与「写入 NFO」已按需要开启, 且媒体服务器的媒体库指向整理后的目录. 媒体服务器读取本地文件, 不需要 Token.
    - **Amane 的图片地址** (`/api/resources/...`): 媒体服务器及其插件无法附加请求头, 必须使用图片 Token. 在图片地址后附加查询参数 `token=<图片 Token>`. 图片 Token 保存在数据目录的 `image_token` 文件中, 启动日志中也会打印.

    图片 Token 只能读取图片资源. 经它访问的图片代理地址只返回 Amane 已缓存的图片, 未缓存时返回 404, 可以先访问一次影片详情页或在刮削时下载图片. 详见 [对接 Emby / Jellyfin](media-server.md).

??? question "Emby / Jellyfin 不显示刮削的元数据"
    NFO 只在整理时写出. 依次核对:

    - 媒体库已开启「写入 NFO」, 并对相应文件执行过整理.
    - 媒体服务器侧已开启 NFO 作为本地元数据来源, 并关闭在线元数据与图片下载, 避免覆盖.
    - NFO 与视频同名: NFO 模板默认 `{link_dir}/{video_name}.nfo`. 修改过视频路径模板的命名方式, 而 NFO 模板仍为 `{link_dir}/{number}.nfo` 时两者不同名, 媒体服务器不会读取, 应改为 `{video_name}.nfo`.

    详见 [NFO](media-server.md#nfo).

??? question "能否导入已有 NFO, 或复用本地图片"
    不能. 刮削不读取本地文件: 数据从站点流向 Amane 数据库, 再经整理输出到磁盘, 是单向过程; 编辑与刮削只修改数据库, 更新磁盘文件需要整理. 需要以本地数据为来源时, 把它实现为一个服务, 再通过自定义插件加入类型路由. 详见 [插件](plugins.md).

??? question "NFO 中的标题能否自定义"
    NFO 内容固定, 不提供模板; `<title>` 与 `<originaltitle>` 为「番号 + 空格 + 标题」. 需要不同的显示标题时, 修改影片的标题字段. 详见 [对接 Emby / Jellyfin](media-server.md#nfo).

??? question "如何在 Amane 中播放视频"
    Amane 不内置播放源: 详情页的播放面板由播放源插件提供, 预告片可以直接播放; 本地视频的日常观看建议交给 Emby / Jellyfin. 详见 [播放](playback.md).

??? question "视频在网盘, 如何供 Emby / Jellyfin 使用"
    媒体库指向网盘挂载目录, 把「链接路径模板」设为本地目录, 链接方式选 STRM 或符号链接: 视频在网盘中整理, NFO、图片与字幕写到本地, 媒体服务器只读本地目录. 链接路径必须是库外路径, Docker 中还需位于 `AMANE_SAFE_DIRS` 内. 详见 [网盘场景](media-server.md#cloud).

## 反馈问题

??? question "如何反馈问题"
    在 GitHub 按 [Issue 模板](https://github.com/sqzw-x/amane/issues/new/choose) 提交, Bug 报告需要填写操作系统、Amane 版本、现象与复现步骤.

    请同时附上日志:

    - 服务日志: 侧栏「运行 → 日志」, 或日志目录中的 `app.log`.
    - 单个任务的记录: 任务详情中的「任务记录」, 或日志目录中的 `tasks/task-<任务 ID>/`.
    - 相关配置: 数据目录中的 `config.toml`.

    提交前删除其中的 Token、Cookie、API 密钥等敏感信息.
