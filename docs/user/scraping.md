# 刮削

刮削是从多个站点获取影片与演员元数据的过程. 本页说明刮削的入口、类型识别、站点与类型路由、字段取值规则、缓存与重新刮削、演员刮削、LLM 翻译、图像超分与 r18.dev 数据源, 以及 设置 → 影片刮削 / 演员刮削 / LLM 翻译 / 图像超分 四个分区的全部设置项. 网络、代理与站点登录见 [网络与站点访问](network.md).

!!! tip "推荐做法"
    多数情况下保持默认设置即可: 默认类型路由已按内容类型排好站点顺序. 需要调整时, 先用「字段优先级」与「字段排除」处理个别字段, 只有确实要增减站点时再修改「类型路由」.

## 刮削入口 {#entry}

刮削的输入是番号. 以下入口按番号来源列出, 媒体库入口用于从本地文件识别番号.

| 入口 | 位置 | 说明 |
|------|------|------|
| 按番号刮削 | 任务 → 提交任务 → 刮削 | 填写番号, 内容类型可留空 |
| 批量番号 | 任务 → 批量刮削 | 用 Liquid 模板生成一组番号, 提交前可预览 |
| 订阅 | 订阅源设置自动刮削 | 从 RSS / Atom 条目中解析番号, 见 [订阅](feeds.md) |
| 智能体 | 首页对话 | 用自然语言提交刮削, 见 [智能体](agent.md) |
| 重新刮削 | 片库 → 影片详情 → 重新刮削; 片库勾选 → 批量重新刮削 | 菜单内可选「刮削」或「强制刮削」, 见 [缓存](#cache) |
| 定时重新刮削 | 定时任务 → 重新刮削 | 见 [重新刮削](#rescrape) |
| 媒体库 (可选) | 自动化级别「监控+刮削」、扫描、文件列表中的「刮削」/「指定番号刮削」/「批量刮削」 | 从文件路径识别番号, 见 [媒体库](libraries.md) |

任务的执行、进度与结果查看见 [任务与定时任务](tasks.md).

## 刮削流程 {#pipeline}

一次刮削按以下顺序执行:

1. **确定番号与内容类型**: 来自用户输入、订阅条目或文件路径, 见 [番号与类型识别](#identify).
2. **请求站点**: 请求该类型「类型路由」中的站点. 已有站点快照且启用元数据缓存时, 对应站点不再请求.
3. **按字段取值**: 每个字段按自己的站点顺序取值, 见 [字段优先级与字段排除](#field-priority).
4. **翻译**: 启用 LLM 翻译时翻译标题与剧情, 并完成简繁转换, 见 [LLM 翻译](#llm).
5. **下载图片**: 按「刮削时下载」下载封面、海报、剧照, 按需裁切海报与超分.
6. **写入影片**: 已锁定的字段保留现值. 启用演员自动刮削时, 为尚未刮削过的演员提交演员刮削任务.

只要有一个站点返回结果, 刮削即视为成功; 各站点的成功、失败与缓存命中情况记录在任务结果中.

## 番号与类型识别 {#identify}

### 内容类型 {#content-types}

内容类型由番号的形态推断, 决定刮削时使用哪条类型路由.

| 类型 | 识别依据 |
|------|----------|
| 有码 | 字母前缀加数字的常见番号 (`MIDV-123`), 以及 DMM 连写形态 (`MIDV00123`) |
| 无码 | 已知无码前缀 (`HEYZO`、`heydouga`、`S2M` 等)、`n1234` / `k1234`、六位日期号 (`010115-001`) |
| FC2 | 含 `FC2` 的番号, `FC2-PPV-` 与 `FC2-` 两种写法视为同一番号 |
| 国产 | `MD` 开头的国产番号、`MKY-` 系列 |
| 素人 | 带数字前缀的番号 (`300MIUM-123`)、`SIRO`, 以及常省略数字前缀的素人标签 (`ARA`、`LUXU`、`MAAN` 等) |
| 欧美 | 片商加日期 (`Vixen.23.01.15`)、`KIN8-1234`, 以及其它未识别形态 |
| 动漫 | 只依据路径关键词 (`getchu`、`里番`、`裏番`) |

类型属于影片本身: 只在影片首次创建时确定, 之后不随文件增删或重新刮削改变, 也不能在编辑界面修改. 类型决定该影片使用哪条类型路由.

!!! note "无码标记与类型"
    文件名或目录中的「无码」「破解」「流出」等是文件的马赛克标记, 与影片类型相互独立: 有码影片的破解版文件, 其影片类型仍是有码.

### 手工指定番号与类型 {#manual-number}

「指定番号刮削」与「任务 → 提交任务 → 刮削」可以填写番号与内容类型:

- 番号按填写内容原样使用, 不做大写与补横线处理. 多数站点比对时忽略大小写与短横线, 仍建议按 `MIDV-123` 的常见写法填写.
- 内容类型留空时按填写的番号推断; 指定后本次刮削按该类型的路由请求站点.
- 指定的类型只在创建新影片时写入. 影片已存在时, 指定类型只改变本次刮削请求的站点, 不改变影片记录的类型.

不同入口对类型的取值不同:

| 入口 | 类型来源 |
|------|----------|
| 文件刮削、扫描 | 文件路径 |
| 指定番号刮削、按番号刮削 | 填写的类型; 留空时按番号推断 |
| 影片详情 → 重新刮削 | 按番号重新推断 |
| 片库批量重新刮削、重新刮削任务 | 影片已记录的类型 |

### 从文件路径识别 (媒体库) {#from-path}

只在使用媒体库时涉及: 扫描与文件刮削依据文件名识别番号, 文件名识别不到时依次尝试各级父目录名. 识别时统一转为大写, 补齐短横线, 并去掉分集 (`-CD1`、`-A`)、中字 (`-C`) 与分辨率 (`1080P`、`4K`) 等标记.

| 文件名 | 番号 | 类型 |
|--------|------|------|
| `MIDV-123-C.mp4` | `MIDV-123` | 有码 |
| `heyzo_1234.mp4` | `HEYZO-1234` | 无码 |
| `FC2-PPV-1234567.mp4` | `FC2-1234567` | FC2 |
| `ARA-423.mp4` | `261ARA-423` | 素人 |
| `MD0165-1.mp4` | `MD0165-1` | 国产 |
| `vixen.23.01.15.mp4` | `Vixen.23.01.15` | 欧美 |

目录名会改变类型判定: 路径中有一段名为 `getchu`, 或以 `里番` / `裏番` 开头时类型为动漫; 以 `欧美` 开头时类型为欧美. 识别不到任何已知形态时, 以清理后的文件名作为番号, 类型为欧美.

## 类型路由 {#content-routes}

「设置 → 影片刮削 → 类型路由」为每种内容类型设置一条有序站点列表. 它有两个作用:

- **决定请求哪些站点**: 刮削只请求该类型路由中的站点. 字段优先级与字段排除不会增加请求.
- **决定默认取值顺序**: 未单独设置的字段按路由顺序取值.

默认值:

| 类型 | 默认路由 |
|------|----------|
| 有码 | dmm → javdb → javbus → official |
| 无码 | javdb → javbus → avsox → freejavbt |
| FC2 | javdb → fc2ppvdb → fc2 → freejavbt → airav |
| 国产 | iqqtv → javdb → airav → freejavbt |
| 素人 | mgstage → dmm → javdb → javbus |
| 欧美 | theporndb → javdb → freejavbt |
| 动漫 | getchu → dmm → javdb |

把某个类型的路由清空即关闭该类型的刮削, 此时该类型的刮削任务失败并提示「没有可用来源」. 已禁用或未安装的插件来源可以留在路由中, 刮削时跳过.

## 字段优先级与字段排除 {#field-priority}

两项设置都按字段生效, 只在该类型路由内部调整顺序, 不在路由中的站点无效:

- **字段优先级**: 只列出需要提前的站点. 这些站点按列出顺序排到前面, 路由中的其余站点保持原顺序跟在后面.
- **字段排除**: 列出该字段不采用的站点. 同一站点同时出现在两项中时以字段排除为准. 某站点被所有字段排除时不再请求.

可设置的字段: 标题、演员、标签、发行日期、时长、导演、系列、制作商、发行商、剧情、海报、封面、预告片、剧照、评分.

!!! example "示例"
    有码影片使用默认路由 dmm → javdb → javbus → official, 并设置:

    - 字段优先级 → 标题: javdb, airav
    - 字段排除 → 演员: dmm

    结果:

    | 字段 | 取值顺序 |
    |------|----------|
    | 标题 | javdb → dmm → javbus → official (airav 不在有码路由中, 忽略) |
    | 演员 | javdb → javbus → official |
    | 其余字段 | dmm → javdb → javbus → official |

取值规则:

- 标题、剧情、制作商等单值字段取顺序中第一个非空值, 前面的站点为空时继续向后取.
- 海报、封面、预告片、评分按顺序合并各站点的结果; 剧照按站点顺序下载, 取到即停止.

### 字段语言偏好 {#field-language}

「字段语言偏好」为标题、剧情、演员、导演、标签、系列、发行商、制作商设置目标语言 (简体中文、繁体中文、日语、英语), 默认均为简体中文. 它有三个作用:

- 支持多语言的站点 (iqqtv、r18dev) 按该语言请求对应版本.
- LLM 翻译把标题与剧情翻译为该语言.
- 中文文本按该语言完成简繁转换.

## 图片下载与海报裁切 {#images}

「刮削时下载」决定刮削时下载到本地的图片类型, 默认为封面、海报、剧照. 预告片文件较大, 默认不下载. 未下载的封面、海报、剧照在打开影片详情页时按需下载.

海报缺失或明显偏矮时, 从封面右侧裁切生成海报:

- 「裁切海报」开启时生效.
- 已有海报的高度不低于封面高度 × 「海报裁切跳过阈值比例」时不裁切.
- 裁切宽高比为「海报裁切比例」.

裁切结果不满意时可以在影片详情页手动裁切, 见 [片库与浏览](browse.md).

## 缓存 {#cache}

刮削使用两种缓存, 可分别启用:

| 缓存 | 内容 | 位置 |
|------|------|------|
| 元数据缓存 | 每个站点上次返回的原始结果 (站点快照), 按站点与语言分别保存 | 随影片或演员保存在数据库中 |
| 译文缓存 | LLM 翻译结果, 以原文、目标语言、字段与提示词为键 | 数据目录下的 `translations.db` |

启用元数据缓存时, 已有快照的站点不再请求, 只请求没有快照或上次失败的站点; 取值仍按当前设置重新计算, 因此修改字段优先级、字段排除或类型路由后, 重新刮削即可生效. 站点快照可以在影片详情的「对比来源」与演员详情的「刮削来源快照」中查看.

| 操作 | 元数据缓存 | 译文缓存 | 效果 |
|------|:---:|:---:|------|
| 刮削 (默认) | 使用 | 使用 | 只补请求缺失的站点, 相同原文不重复翻译 |
| 强制刮削 | 不使用 | 不使用 | 重新请求全部站点并重新翻译 |
| 提交任务时只勾选「译文缓存」 | 不使用 | 使用 | 重新请求全部站点, 原文未变时不消耗 LLM 用量 |

任务提交表单与媒体库扫描的「使用缓存」可以单独勾选「元数据缓存」与「译文缓存」.

译文缓存的行为:

- 不同影片的相同原文只翻译一次, 同时进行的相同翻译也只请求一次.
- 修改系统提示词或字段提示词后, 旧译文自动失效, 不需要手动清理.
- 更换模型不会使旧译文失效. 需要按新模型重新翻译时, 删除 `translations.db`; 该文件只是缓存, 删除后自动重建.

## 重新刮削 {#rescrape}

重新刮削任务定期更新最久未更新的影片或演员, 用于随站点数据更新内容, 或在修改设置后批量应用新设置. 在「任务 → 提交任务」或「定时任务」中选择「重新刮削」:

| 参数 | 默认 | 说明 |
|------|------|------|
| 数量上限 | 100 | 每个所选范围单次最多重新刮削的条数, 范围 1–1000 |
| 最小间隔(天) | 不限 | 只处理超过该天数未更新的条目 |
| 范围 | 影片 | 影片与演员可以单独或同时选择, 各自按数量上限计数 |

重新刮削按更新时间从旧到新选取条目, 以低优先级提交普通刮削任务 (使用缓存), 不会抢占用户手动提交的任务. 影片按已记录的类型选择路由. 演员范围包括已经刮削过的演员, 这一点与 [自动刮削](#actor-scraping) 不同. 定时任务的设置方法见 [任务与定时任务](tasks.md).

## 字段锁定 {#locks}

影片与演员的字段都可以锁定. 锁定的字段在任何刮削中都保留现值, 其余字段照常更新. 手动修改的内容需要长期保留时, 先锁定再重新刮削. 锁定操作见 [片库与浏览](browse.md).

## 演员刮削 {#actor-scraping}

### 触发方式

- **自动刮削**: 「演员刮削 → 自动刮削」开启 (默认) 时, 影片刮削成功后为影片中尚未刮削过的演员提交演员刮削任务, 已刮削过的演员跳过.
- **手动刮削**: 演员详情页的「刮削」菜单 (可选「强制刮削」), 演员列表的批量刮削.
- **刮削本页空缺**: 演员列表中刮削当前页生日、身高与头像均为空的演员.
- **重新刮削**: 重新刮削任务的范围勾选「演员」.

### 资料来源与头像来源

- **资料来源**按「演员资料优先级」依次填充空缺字段: 生日、出生地、身高、三围、罩杯、简介等单值字段取第一个非空值, 各来源的别名合并.
- **头像来源**按「头像来源优先级」取头像, 优先于资料来源附带的图片.
- 已锁定的字段保留现值.

### 性别 {#gender}

性别决定演员刮削请求哪些站点:

| 演员性别 | 请求的站点 |
|----------|------------|
| 女 | 全部资料来源与头像来源 |
| 男 | 覆盖男性的站点; minnano 与 gfriends 跳过 |
| 未知 | 只请求同时覆盖两性的站点 (javdb、wikipedia、theporndb、avbase), 因此不会从 gfriends 获取头像 |

站点能够判断出演者性别时, 影片刮削会把性别写入性别为空的演员; 资料来源也可以补充性别. 性别也可以在演员编辑界面或演员列表的「批量性别」中手动设置.

### 维基简介与身材信息 {#wikipedia}

wikipedia 来源先在 Wikidata 中检索演员, 只采用描述或职业属于成人影片行业且名字相符的实体, 然后读取维基百科词条:

- **简介**: 取词条导语以及人物、简历、经历等章节, 作品列表、脚注等章节不采用.
- **语言优先级**: 「设置 → 影片刮削 → 站点配置 → wikipedia → 语言优先级」决定读取哪种语言的词条, 按顺序取第一个有正文的词条, 默认为中文 → 日文 → 英文. 中文词条读取简体版本. 该设置不影响 Wikidata 的检索.
- **身材信息**: 从词条信息框读取身高、三围与罩杯; 信息框没有身高时使用 Wikidata 的身高.
- **性别**: 取自 Wikidata.

### gfriends 头像

gfriends 从「gFriends 仓库」读取头像索引, 索引缓存在数据目录中. 访问 GitHub 受限时, 可以把仓库地址改为镜像, 或为 gfriends 配置站点代理 (见 [网络与站点访问](network.md#proxy)).

## LLM 翻译 {#llm}

LLM 翻译在刮削时把标题与剧情翻译为「字段语言偏好」中的目标语言, 并完成中文简繁转换.

!!! warning "简繁转换同样需要启用 LLM 翻译"
    简繁转换不调用模型, 但只在「启用 LLM 翻译」开启且填写了「API 密钥」时执行. 未启用时标题与剧情保留站点原文.

### 翻译判定

| 原文 | 目标语言为中文时 |
|------|------------------|
| 含假名 (日文) | 调用 LLM 翻译 |
| 只含 ASCII 字符 (英文) | 调用 LLM 翻译 |
| 其它 (中文) | 按目标语言做简繁转换, 不调用 LLM |

只含汉字、不含假名的日文按中文处理, 只做简繁转换. 翻译失败或模型返回空结果时保留原文, 不影响刮削结果, 下次刮削重新翻译.

### API 协议

| API 类型 | 协议 | API 端点 |
|----------|------|----------|
| Chat | OpenAI Chat Completions | OpenAI 或任意兼容服务的地址, 默认 `https://api.openai.com/v1` |
| Responses | OpenAI Responses | 支持 Responses 接口的服务 |
| Anthropic | Anthropic Messages | Anthropic 端点 |

翻译请求经由「设置 → 网络 → 代理」发出, 单次请求超时 60 秒, 按「每秒请求上限」独立限速. 翻译与智能体的凭据、模型分别配置, 互不影响.

### 自定义提示词

发送给模型的系统提示词由三段组成: 指令 + 字段说明 + 输出约束.

- **系统提示词**替换指令部分. 留空时使用内置指令「你是专业的影视元数据翻译. 将用户提供的文本翻译为{target_lang}.」
- **字段提示词**按字段替换字段说明. 内置说明: 标题为「这是一部影片的标题, 翻译应简洁自然, 保留专有名词与番号.」, 剧情为「这是一部影片的简介, 完整通顺地翻译全部内容.」
- **输出约束**固定为只输出译文, 不能修改.

两种提示词都可以用 `{target_lang}` 引用目标语言名 (简体中文、繁體中文、日本語、English), 其它花括号按原样保留. 单条提示词最长 2000 字符. 留空或只含空白等同于未设置.

```text title="系统提示词示例"
你是成人影片元数据的专业译者. 将用户提供的文本翻译为{target_lang}, 人名保留原文, 不添加注释.
```

## 图像超分 {#upscale}

图像超分对分辨率较低的封面与海报做放大处理, 结果直接覆盖本地文件, 图片地址不变.

### 触发方式

- **刮削时超分**: 开启后, 刮削下载的首张封面、海报 (含裁切生成的海报) 与手动裁切的图片满足阈值时立即超分. 剧照不超分.
- **超分任务**: 「任务 → 提交任务 → 超分」或定时任务, 遍历全部本地图片, 补做未超分的图片. 可设置最大尺寸阈值、最大文件大小阈值 (留空沿用设置) 与数量上限 (默认 200). 「刮削时超分」关闭时, 可以用定时任务在空闲时段处理.

图片同时满足以下两个条件时超分: 最长边小于「超分尺寸阈值」, 且文件大小不超过「超分文件大小阈值」. 已超分且文件未变化的图片不重复处理.

### 预设与平台

| 预设 | 工具 | 倍率 |
|------|------|------|
| waifu2x-photo-2x (默认) | waifu2x-ncnn-vulkan, 照片模型 | 2 倍 |
| Real-ESRGAN-photo-4x | Real-ESRGAN-ncnn-vulkan, 通用照片模型 | 4 倍 |

| 平台 | waifu2x | Real-ESRGAN |
|------|:---:|:---:|
| macOS | :material-check: | :material-check: |
| Windows | :material-check: | :material-check: |
| Linux x86_64 | :material-check: | :material-check: |
| Linux ARM64 | :material-check: | |

超分工具在首次使用时从 GitHub 下载到数据目录的 `tools/` 下, 该下载不使用「设置 → 网络」的代理. Linux 上的 waifu2x 使用修正过的构建, 可以在没有 Vulkan 设备的环境 (如 Docker 容器、NAS) 以 CPU 运行, 也支持 ARM64; 在这类环境中使用 waifu2x 预设. 当前平台没有可用工具时, 超分失败并在任务日志中提示不支持的平台, 刮削不受影响.

## r18.dev 数据源 {#r18dev}

r18dev 是离线数据源: r18.dev 以 PostgreSQL 数据包的形式发布完整目录, Amane 把它导入用户自备的 PostgreSQL 实例, 刮削时直接查询, 不访问网站. 数据包内容对应 DMM 目录, 提供日文与英文标题、剧情与演员名, 图片使用 DMM 的图片地址.

### 启用步骤

1. 准备 PostgreSQL 实例, 以及一个具备 CREATEDB 与 CREATEROLE 权限的账号.
2. 在「设置 → r18」中填写「PostgreSQL 连接串」(形如 `postgresql://user:pass@host:5432`) 与「数据包地址」(r18.dev 发布的数据包下载地址).
3. 确认可以执行 `psql`: Docker 镜像已包含; 桌面版与源码安装需要自行安装 PostgreSQL 客户端, 不在 PATH 中时填写「psql 路径」.
4. 在「任务 → 提交任务」中提交「R18 导入」. 需要定期更新时, 在「定时任务」中创建 R18 导入任务.
5. 把 `r18dev` 加入需要的类型路由 (例如有码). r18dev 不在默认路由中.

| 设置项 | 默认 | 说明 |
|--------|------|------|
| PostgreSQL 连接串 | 空 | 为空时 r18dev 来源禁用, 刮削时直接跳过 |
| 数据库名 | `r18dev` | 导入器自动创建 |
| 只读角色 / 只读角色密码 | `r18dev_readonly` | 刮削查询使用的账号, 导入器自动创建并授权; PostgreSQL 可从其它主机访问时应修改默认密码 |
| 查询超时 (秒) | 30 | 单条查询的超时 |
| 数据包地址 | 空 | 为空时无法导入 |
| psql 路径 | `psql` | 导入使用的 psql 可执行文件 |

### 导入过程

1. 检查数据包版本, 与已导入的版本相同时跳过 (勾选「强制重新导入」可忽略版本比对).
2. 下载并解压数据包.
3. 导入临时数据库并校验表结构.
4. 校验通过后替换旧数据库, 并创建只读角色. 校验失败时保留上一次成功导入的数据.

导入失败或尚未导入时, r18dev 返回空结果, 不影响其它站点.

## 刮削排障 {#troubleshooting}

任务结果按站点列出成功、失败与缓存命中, 失败项附带原因 (见 [网络检测的原因说明](network.md#reasons)). 需要原始响应时, 开启「设置 → 日志 → 调试捕获」后重新刮削.

| 现象 | 处理 |
|------|------|
| 提示「内容类型 X 没有可用来源」 | 该类型路由为空或其中站点都不可用, 检查类型路由 |
| 站点结果为「需要登录」 | 为该站点配置 Cookie, 见 [站点登录](network.md#credentials) |
| 站点结果为「Cloudflare 人机验证」 | 启用浏览器渲染, 见 [浏览器渲染](network.md#browser) |
| 站点结果为请求超时、网络错误、地域受限 | 检查代理, 使用 [网络检测](network.md#network-check) 确认站点可访问 |
| 站点结果为「无可用元数据」 | 站点没有该番号, 或检索结果与番号不一致; 检查番号是否识别正确, 必要时用「指定番号刮削」 |
| 番号识别错误 | 用「指定番号刮削」填写正确番号, 或修改文件名后重新刮削 |
| 类型识别错误, 请求了错误的站点 | 用「指定番号刮削」指定内容类型; 影片记录的类型不随之改变, 见 [手工指定番号与类型](#manual-number) |
| 某字段没有更新 | 检查该字段是否已锁定、是否被字段排除; 站点数据已更新时使用「强制刮削」 |
| 修改设置后旧影片没有变化 | 设置只对之后的刮削生效; 重新刮削对应影片, 或提交重新刮削任务 |
| 没有翻译 | 检查是否启用 LLM 翻译并填写 API 密钥、字段是否在「翻译字段」中; 只含汉字的日文按中文处理; 翻译失败时查看任务日志 |
| 换模型后译文不变 | 删除数据目录下的 `translations.db` 后重新刮削 |
| 演员没有头像 | 演员性别为「未知」时不请求 gfriends, 设置性别后重新刮削 |
| r18dev 始终无结果 | 检查连接串、R18 导入任务是否成功, 以及 r18dev 是否已加入类型路由 |
