# 任务与定时任务

扫描、刮削、整理等耗时操作都以任务的形式排队, 由任务引擎在后台执行. 本页说明「运行」分组下的三个页面: 「任务」查看与控制任务队列, 「定时任务」按时间自动提交例行任务, 「日志」实时查看服务日志.

## 任务页 {#tasks}

任务页列出全部任务, 默认只显示每条任务链的第一个任务 (链根), 由它派生的任务折叠在其下方.

![任务页](../assets/screenshots/tasks.webp#only-light){ loading=lazy }
![任务页](../assets/screenshots/tasks-dark.webp#only-dark){ loading=lazy }

### 状态

| 状态 | 含义 |
|------|------|
| 排队中 | 等待任务引擎认领 |
| 运行中 | 正在执行; 支持进度上报的任务显示进度条 |
| 已完成 | 执行成功 |
| 失败 | 执行失败或被取消. 被取消的任务失败原因为「已由用户取消」 |

页面顶部按状态与任务类型筛选. 筛选同时匹配子任务: 链根已完成而子任务仍在排队时, 按「排队中」筛选仍能找到这条链.

### 任务树与子任务

有子任务的行显示「N 个子任务」与子任务的状态分布 (如失败数、运行中数), 点击展开. 子任务较多时分批加载, 点击「加载更多」继续. 工具栏的「全部展开」「全部收起」作用于当前页.

点击任务行展开详情:

- 基本信息: ID、根任务、子任务标识、优先级、重试次数、创建时间、开始时间、耗时、状态与进度.
- 任务结果: 刮削与演员刮削按站点分组显示「成功」「缓存」「失败」及失败原因, 并链接到生成的影片或演员; 整理显示已整理、跳过、冲突、失败与剪枝目录数, 并列出「未处理的冲突」. 其它类型完成后显示「任务已完成」.
- 「参数」与「结果」: 折叠的原始 JSON.
- 「实时日志」: 排队中与运行中的任务显示该任务的日志流.

### 取消、重试与删除

| 操作 | 适用状态 | 说明 |
|------|---------|------|
| 取消任务 | 排队中、运行中 | 运行中的任务立即中断网络请求与数据库写入; 正在移动或硬链接文件时, 等当前文件操作完成后才生效 |
| 重试 | 失败 | 以相同参数创建一个新任务. 新任务独立成链, 不归属原任务链 |
| 任务记录 | 已完成、失败 | 下载 `task-{id}-record.zip`: 任务日志、配置快照 (密钥已脱敏)、出站 HTTP 记录与刮削站点明细, 用于排障或提交 Issue |
| 删除 | 已完成、失败 | 删除任务记录及其任务日志目录 |

工具栏的批量操作作用于**当前筛选**范围内的全部任务:

- 「取消」: 取消排队中与运行中的任务.
- 「重试失败」: 重试失败的任务.
- 「清除已完成」/「清除失败」: 删除对应状态的任务. 仍有未删除子任务的链根会保留, 以免子任务失去归属.

### 提交任务与批量刮削

- 「提交任务」: 选择任务类型并填写参数后提交. 表单中标注「覆盖媒体库设置」的字段只作用于本次提交.

![提交任务对话框](../assets/screenshots/submit-task.webp#only-light){ loading=lazy }
![提交任务对话框](../assets/screenshots/submit-task-dark.webp#only-dark){ loading=lazy }
- 「批量刮削」: 用 Liquid 模板生成番号列表, 每行一个, 支持循环与过滤器; 预览自动去除重复番号, 单次最多提交 1000 个.

```liquid
{% for i in (101..120) %}ABC-{{ i }}
{% endfor %}
```

### 暂停任务引擎

标题旁的「暂停」按钮使任务引擎停止认领新任务: 已在运行的任务继续执行, 新任务照常排队. 点击「恢复」继续认领. 暂停状态不写入配置, 服务重启后自动恢复.

## 任务类型 {#types}

| 类型 | 作用 | 提交方式 |
|------|------|---------|
| 扫描 | 扫描媒体库的新增与失效文件, 新文件入库, 可派生刮削 | 媒体库页、提交任务、智能体 |
| 刮削 | 联网获取一部影片的元数据与图片 | 片库、媒体库、订阅、提交任务、批量刮削、智能体; 文件监控按[自动化级别](libraries.md)提交 |
| 整理 | 按路径模板把已刮削的文件写入媒体库, 并写入 NFO 与图片 | 媒体库页、提交任务、智能体; 开启自动整理的库在刮削后自动提交 |
| 演员刮削 | 获取演员资料与头像 | 演员页、提交任务、智能体; 影片刮削后自动提交 |
| 重新刮削 | 选取最久未更新的影片或演员, 批量提交刮削 | 提交任务、定时任务 |
| 扫描无效文件 | 只读遍历媒体库, 生成无效文件、残留目录与空目录的清理清单 | 媒体库页、提交任务 |
| 删除 | 按复核过的清理清单删除文件与目录 | 媒体库的清理面板 |
| 清理 | 删除磁盘上已不存在的文件索引与无影片引用的资源文件; 不删除影片 | 提交任务、定时任务 |
| 超分 | 对低分辨率的图片执行超分 | 提交任务、定时任务 |
| R18 导入 | 导入 r18.dev 数据包 | 提交任务、定时任务 |
| 语义索引 | 为封面与剧照建立语义索引 (可只索引封面或只索引剧照), 供[语义检索](browse.md#semantic-search)使用; 首次运行时自动下载模型 | 提交任务、定时任务 |

扫描、整理、扫描无效文件与删除的细节见 [媒体库](libraries.md) 与 [整理与路径模板](organize.md); 刮削、演员刮削、重新刮削、超分与 R18 导入见 [刮削](scraping.md).

### 任务链 {#chains}

部分任务在成功后派生子任务, 子任务挂在父任务下方:

| 父任务 | 子任务 | 条件 |
|--------|--------|------|
| 扫描 | 刮削 | 按扫描的「刮削范围」, 每个文件一个 |
| 刮削 | 演员刮削 | 「设置 → 演员刮削」开启自动刮削, 且演员尚未刮削过 |
| 刮削 | 整理 | 媒体库开启自动整理, 且刮削的是库中文件 (按番号刮削不整理) |
| 重新刮削 | 刮削、演员刮削 | 每个选中的影片或演员一个 |

- 子任务只在父任务成功后创建; 父任务失败或被取消时不派生.
- 自动派生的子任务以较低优先级排队, 不抢占手动提交的任务.
- 同一演员已有排队中或运行中的演员刮削时, 复用该任务, 不重复创建.

### 缓存控制 {#cache}

刮削、扫描与演员刮削的「使用缓存」选项决定复用哪些已有数据:

| 选项 | 勾选 | 不勾选 |
|------|------|--------|
| 元数据缓存 | 复用各站点上次获取的数据, 只请求缺失或失败的站点 | 全部站点重新获取 |
| 译文缓存 | 命中时跳过 LLM 翻译 | 重新翻译并刷新缓存 |

两项都不勾选即强制刷新, 等同片库中的「强制刮削」. 扫描的缓存选项原样传给其派生的刮削. 缓存的范围与失效规则见 [刮削](scraping.md).

### 任务引擎与配置变更 {#engine}

同时执行的任务数由「设置 → 任务引擎 → 并发数」控制, 见 [配置参考](configuration.md).

修改配置**不会取消运行中的任务**: 保存设置后, 已在运行的任务按原配置执行完毕, 之后认领的任务使用新配置. 过渡期间新旧配置的任务可能同时运行, 总并发暂时高于设置值.

服务关闭时仍在运行的任务标记为失败, 可在重启后重试.

## 定时任务 {#schedules}

定时任务按设定的时间自动提交例行任务. 可调度的任务类型为: 清理、超分、R18 导入、重新刮削. 扫描与刮削由[文件监控](libraries.md)与[订阅](feeds.md)驱动, 不在此列.

![定时任务页](../assets/screenshots/schedules.webp#only-light){ loading=lazy }
![定时任务页](../assets/screenshots/schedules-dark.webp#only-dark){ loading=lazy }

### 创建定时任务

1. 打开「定时任务」, 点击「新建定时任务」.
2. 选择任务类型并填写参数, 参数项与「提交任务」中的同名类型一致.
3. 填写「名称」(可选, 留空时显示任务类型), 设置「运行时间」, 保存.

列表中每个定时任务显示启用状态、运行时间摘要与 Cron 表达式、「下次执行」时间, 以及任务类型与参数摘要 (如「每类 100 条」「超过 30 天未更新」). 参数中未填写的项显示为「沿用配置」.

| 操作 | 说明 |
|------|------|
| 启用开关 | 停用后不再自动提交 |
| 立即触发 | 把下次执行时间设为当前, 在一分钟内提交任务. 只对已启用的定时任务生效 |
| 编辑 | 只能修改名称、运行时间与启用状态; 参数只读显示 |
| 删除 | 删除定时任务, 不影响已提交的任务 |

!!! note
    修改任务类型或参数须删除后重新创建.

### 运行时间 {#cron}

「运行时间」提供五种模式:

| 模式 | 设置方式 |
|------|---------|
| 每天 | 选择时、分 |
| 每周 | 选择星期 (可多选) 与时、分 |
| 每月 | 选择日期与时、分 |
| 间隔 | 每 N 分钟, 或每 N 小时的第几分钟 |
| 高级 | 直接输入 5 段 Cron 表达式 (`分 时 日 月 星期`), 与 Linux crontab 相同 |

- 「每天」「每周」「每月」按浏览器的**本地时间**选择, 保存时换算为 UTC. 表单下方显示生成的 Cron 表达式与文字摘要.
- 「高级」模式的表达式按 **UTC** 解释, 不做换算.
- 服务每 60 秒检查一次到期的定时任务, 实际提交时间最多晚于设定时间一分钟.

```text
0 18 * * *     每天 UTC 18:00 (北京时间次日 02:00)
*/30 * * * *   每 30 分钟
0 3 * * 1      每周一 UTC 03:00
```

## 日志页 {#logs}

「日志」页实时显示服务日志. 页面在浏览器中保留最近 5000 条, 切换页面不丢失, 刷新页面或点击「清空」后清除; 历史日志在日志目录的 `app.log` 中, 单个任务的完整日志在[任务记录](#tasks)中.

每条日志显示时间、级别、来源模块与消息, 其后是结构化字段 (`键=值`), 如 `task_id`、`status`、`error`. 字段按值类型着色, 错误与 HTTP 状态码使用醒目颜色.

![日志页](../assets/screenshots/logs.webp#only-light){ loading=lazy }
![日志页](../assets/screenshots/logs-dark.webp#only-dark){ loading=lazy }

### 筛选

- **级别**: 点击「调试」「信息」「警告」「错误」「严重」按钮切换, 可多选; 不选即显示全部.
- **搜索**: 支持按字段查询, 语法错误时在输入框下方提示; 纯文本输入回退为对消息与来源的模糊搜索.

```text
level:ERROR AND source:worker
task_id:42
```

### 自动滚动

「自动滚动」开启时, 新日志到达后列表保持在底部. 向上滚动阅读时不会被拉回底部; 关闭后再开启会立即跳到最新一条.

服务输出哪些级别的日志由「设置 → 日志 → 级别」决定, 日志页只能在已输出的日志中筛选.
