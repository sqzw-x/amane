# 网络与站点访问

本页说明 Amane 如何访问刮削站点: 代理与按站点代理、超时、重试与限速、TLS 指纹、浏览器渲染 (用于 Cloudflare 验证)、需要登录的站点, 以及「网络检测」页的用法. 网络环境受限, 或刮削结果出现超时、拦截、需要登录时阅读本页.

!!! tip "推荐做法"
    1. 在「设置 → 网络 → 代理」填写代理地址.
    2. 打开「网络检测」页, 确认各站点可访问.
    3. 对不可访问的站点按 [结论解读](#reasons) 处理: 不需要代理的站点关闭「使用代理」, 需要登录的站点配置 Cookie, 出现 Cloudflare 人机验证的站点启用浏览器渲染.

设置保存后立即生效, 不需要重启, 也不会中断正在执行的任务 (已开始的任务按旧设置完成).

## 代理 {#proxy}

「设置 → 网络 → 代理」是全局代理, 支持 HTTP 与 SOCKS 代理, 地址必须带协议:

```text
http://127.0.0.1:7890
socks5://127.0.0.1:1080
socks5h://127.0.0.1:1080
```

`socks5h://` 经由代理解析域名, 适用于本地 DNS 受污染的网络.

全局代理用于站点请求、图片下载、订阅源拉取、LLM 翻译、插件播放源、更新检查与本地浏览器 (Patchright / Camoufox). Solver 服务与图像超分工具的下载不使用该代理.

### 按站点代理或直连 {#site-proxy}

「设置 → 影片刮削 → 站点配置」中每个站点有两项代理设置:

| 使用代理 | 站点代理 | 该站点的请求 |
|:---:|------|------|
| 开启 (默认) | 留空 | 使用全局代理 |
| 开启 | 填写 | 使用站点代理 |
| 关闭 | — | 直连, 不使用任何代理 |

站点代理的地址格式与全局代理相同, 保存时校验协议.

- 站点设置只作用于该站点自身的域名 (默认域名与「自定义域名」). 图片 CDN 等其它域名仍使用全局代理.
- 演员站点 (minnano、gfriends、wikipedia 等) 也在同一列表中设置.
- 经由浏览器的请求不受站点代理与「使用代理」影响: 本地浏览器只使用全局代理, Solver 服务使用其自身的代理配置.

!!! example "示例"
    国内可直连的站点关闭「使用代理」, 其余站点使用全局代理; 访问 GitHub 受限时, 为 gfriends 单独填写站点代理.

## 超时与重试 {#retry}

| 设置项 | 默认 | 说明 |
|--------|------|------|
| 请求超时 | 10 秒 | 单次 HTTP 请求的超时, 范围 5–300 |
| 最大重试次数 | 2 | 首次请求之外的重试次数, 默认最多发出 3 次请求; 0 表示只发一次 |

以下情况重试: 超时、连接错误, 以及 HTTP 408、429、503、504. 重试间隔约为 2 秒、5 秒、8 秒依次递增. 其它 4xx 状态 (如 404) 不重试. [网络检测](#network-check) 对每个站点只发一次请求, 不重试.

## 限速 {#rate-limit}

每个域名独立限速, 请求均匀发出, 不允许突发. 短时间内的突发请求容易触发站点的反爬机制.

| 设置 | 位置 | 默认 | 作用范围 |
|------|------|------|----------|
| 速率限制 (按域名) | 设置 → 网络 → 速率限制 | 空 | 填写的域名, 如 `javdb.com` |
| 速率限制 (按站点) | 设置 → 影片刮削 → 站点配置 → 速率限制 | 2 | 该站点的默认域名与自定义域名 |
| 默认速率限制 | 设置 → 网络 → 默认速率限制 | 5 | 其它域名, 如图片 CDN |

单位是每秒请求数, 范围 0.1–100. 同一域名同时有多项设置时, 按上表从上到下取第一项. 域名按完整主机名匹配, `javdb.com` 不覆盖 `www.javdb.com`. 本机地址 (`localhost`、`127.0.0.1`) 固定为每秒 300 次.

!!! example "示例"
    在「速率限制」中添加 `javdb.com`, 值为 `0.5`, 即对 javdb.com 每 2 秒最多发出一次请求.

LLM 翻译的限速在「设置 → LLM 翻译 → 每秒请求上限」中单独设置, 见 [LLM 翻译](scraping.md#llm).

## 分块下载 {#chunked}

文件大小已知且超过「分块阈值」时, 分成多个分块并行下载. 该机制主要用于预告片与 r18.dev 数据包.

| 设置项 | 默认 | 说明 |
|--------|------|------|
| 分块阈值 | 2 MiB | 超过该大小 (字节) 时分块下载 |
| 分块大小 | 1 MiB | 每个分块的大小 (字节) |
| 下载并发数 | 10 | 同时下载的分块数, 范围 1–50 |

每个分块受「请求超时」约束. 带宽较低时, 分块大小过大或并发数过高会使每个分块都超时, 重试不改变结果; 此时降低下载并发数或分块大小, 或提高请求超时.

## TLS 指纹 {#tls-fingerprint}

部分站点按 TLS 指纹识别非浏览器客户端. Amane 发出的请求模拟 Chrome 与 Firefox 的 TLS 指纹, 不需要设置:

- 进程启动时随机选定一个默认指纹.
- 某个域名返回 HTTP 403 或 406 时, 判定为该指纹被拦截, 换用下一个未试过的指纹重发, 单次请求最多轮换 3 次. 轮换不计入重试次数.
- 轮换成功的指纹对该域名保持, 后续请求直接使用. 保存设置或重启后重新选择.

全部指纹都被拒绝时, 请求以「请求被站点拒绝」失败. 这类拦截通常与 IP 有关, 更换代理出口后重试.

## 浏览器渲染 {#browser}

Cloudflare 人机验证页只能通过执行 JavaScript 越过. 启用浏览器渲染后, 受保护站点的页面经由浏览器取得.

### 后端

「设置 → 网络 → 浏览器渲染 → 浏览器后端」:

| 后端 | 说明 | 桌面版 | Docker | 源码安装 |
|------|------|:---:|:---:|:---:|
| 关闭 (默认) | 不使用浏览器 | :material-check: | :material-check: | :material-check: |
| Patchright | 启动本机安装的 Chrome | | | :material-check: |
| Camoufox | 基于 Firefox 的浏览器, 首次启动时下载 | | | :material-check: |
| Solver 服务 | 外部 FlareSolverr 兼容服务 | :material-check: | :material-check: | :material-check: |

桌面版与 Docker 镜像不包含本地浏览器引擎, 只能使用 Solver 服务; 选择不可用的后端时设置无法保存, 并提示改用 solver. 源码安装经 `just setup` 或 `just sync` 安装全部可选依赖后可以使用 Patchright 与 Camoufox.

| 设置项 | 默认 | 说明 |
|--------|------|------|
| 浏览器后端 | 关闭 | 见上表 |
| 页面请求超时 | 30000 毫秒 | 单个页面的加载超时, 范围 5000–120000 |
| Solver 地址 | `http://127.0.0.1:8191` | FlareSolverr 兼容服务的地址, 仅 Solver 服务后端使用 |

=== "Solver 服务"

    1. 部署 FlareSolverr 或兼容服务, 只在本机或内网开放端口.
    2. 「浏览器后端」选择「Solver 服务」, 「Solver 地址」填写服务地址.
    3. 打开「网络检测」页, 确认受保护的站点可访问.

    Solver 服务自身的出站代理在该服务中配置, Amane 的代理设置不作用于它.

=== "Patchright / Camoufox"

    1. 使用 Patchright 时确认本机已安装 Chrome.
    2. 「浏览器后端」选择对应后端.
    3. 浏览器在首次需要时启动, 使用全局代理; 空闲 10 分钟后关闭.

!!! danger "Solver 服务不能暴露到公网"
    Solver 服务可以代替调用方访问任意地址, 暴露到公网会被滥用. 只监听本机或内网地址.

### 站点浏览器策略

「设置 → 影片刮削 → 站点配置 → 浏览器策略」决定每个站点何时使用浏览器:

| 策略 | 行为 |
|------|------|
| 自适应 (默认) | 先直接请求; 首次遇到 Cloudflare 人机验证后, 该站点改用浏览器, 直到保存设置或重启 |
| 始终 | 该站点的页面一律经由浏览器 |
| 关闭 | 该站点不使用浏览器 |

- 只有 HTML 页面经由浏览器. 图片、接口数据与文件下载始终直接请求, 被拦截时只由 [TLS 指纹轮换](#tls-fingerprint) 处理.
- 同一站点的连续请求复用同一个浏览器会话, 已通过的验证在保存其它设置后仍然保留; 修改浏览器渲染或全局代理设置时重新启动浏览器.
- 插件来源不使用浏览器.

常见的受保护站点: avbase、javlibrary、fc2ppvdb, 以及 minnano 的检索页.

## 站点登录与凭据 {#credentials}

部分站点需要登录或访问凭据, 在「设置 → 影片刮削 → 站点配置」中为对应站点填写:

| 站点 | 凭据 | 缺少时 |
|------|------|--------|
| javdb | Cookie | 无码影片与无码演员的档案无法获取, 结果为「需要登录」; 有码影片与搜索页不受影响 |
| theporndb | API Token | 影片与演员刮削均跳过该站点 |

dmm、mgstage 的年龄确认 Cookie 已内置, 不需要填写. 填写的 Cookie 与内置 Cookie 合并, 同名时以填写的为准.

### 配置 javdb Cookie

1. 在浏览器中登录 javdb.com.
2. 打开浏览器开发者工具, 在「应用」(Application) 或「存储」(Storage) 面板的 Cookie 列表中找到 `javdb.com` 下的 Cookie.
3. 在「站点配置 → javdb → Cookie」中按名称逐项添加, 值取自浏览器. 至少包含登录会话 Cookie.
4. 保存后在 [网络检测](#network-check) 页重试 javdb, 并刮削一部无码影片确认结果不再是「需要登录」.

Cookie 过期后结果重新变为「需要登录」, 按上述步骤更新.

!!! warning "凭据以明文保存"
    Cookie、API Token 与 API 密钥以明文保存在数据目录的 `config.toml` 中. 备份或分享该文件前删除这些值.

站点更换域名时, 可以在「站点配置 → 自定义域名」填写新域名; 该站点的代理与限速设置随之作用于新域名.

## 图片代理 {#image-proxy}

网页中显示的站点图片 (尚未下载到本地的封面、海报等) 经由 Amane 转发: 服务端按本页的网络设置取得图片并缓存到本地, 之后直接从本地读取. 浏览器不直接访问站点.

- 只接受 `http` 与 `https` 地址, 其它地址返回错误.
- 取图失败的地址在 15 分钟内不再请求, 直接返回失败.
- 使用图片 Token 的请求 (如 Emby / Jellyfin 引用的图片地址) 只读取本地缓存, 不触发对外请求, 见 [对接 Emby / Jellyfin](media-server.md).

## 网络检测 {#network-check}

「运行 → 网络检测」逐一请求当前配置中的站点, 判断此刻能否访问. 进入页面时自动检测一次; 「重新检测」对全部站点重新检测, 每一行的「重试」只检测该站点.

### 检测范围与方式

- **范围**: 各类型路由中的站点、演员资料来源与头像来源, 含插件来源. 不在任何路由中的站点不检测, 因此检测范围与刮削范围一致.
- **方式**: 与刮削使用同一套代理、TLS 指纹、限速、Cookie 与浏览器策略; 每个站点只请求一次, 超时为「请求超时」.
- **入口**: 多数站点请求首页. 实际入口不是首页的站点请求实际入口: minnano 请求检索页, gfriends 请求头像索引, prestige 请求商品接口, theporndb 用 API Token 发出一次真实查询, official 请求一个制作商官网 (配置了制作商路由时取其中第一个).

### 结果

页面顶部显示可访问占比与三类结果的数量, 点击某一类只显示该类. 列表按「不可访问」→「无法探测」→「可访问」排序, 列出来源 (标注影片、演员或插件)、结果、原因与耗时.

| 结果 | 含义 |
|------|------|
| 可访问 | 返回了正常页面, 不是拦截页或空页 |
| 不可访问 | 请求失败或返回拦截页, 「原因」列说明类型 |
| 无法探测 | 该站点本次不检测, 不是失败 |

### 无法探测的原因

| 原因 | 说明 |
|------|------|
| 来源不存在或未启用 | 路由中的站点不存在, 或插件已禁用 |
| 该来源不经网络取数据, 读取离线镜像 | r18dev, 见 [r18.dev](scraping.md#r18dev) |
| 缺少凭据, 刮削时会跳过 | 例如 theporndb 未填写 API Token |
| 未提供可探测的地址 / 插件未声明来源 URL | 插件没有提供检测方式 |

### 结论解读 {#reasons}

以下原因同样出现在刮削任务的站点结果中.

| 原因 | 处理 |
|------|------|
| 请求超时 / 网络错误 | 检查代理是否可用; 国内可直连的站点关闭「使用代理」; 网络较慢时提高「请求超时」 |
| 地域受限 | 当前出口 IP 所在地区被站点限制, 更换代理出口 |
| IP 被封禁 / Cloudflare 拦截 | 出口 IP 被站点拒绝, 更换代理出口, 并降低该站点的速率限制 |
| 请求被站点拒绝 | HTTP 4xx; 多为出口 IP 被拒绝; 填写了「自定义域名」时检查域名是否正确 |
| Cloudflare 人机验证 | 启用 [浏览器渲染](#browser) |
| 请求过于频繁 | 降低该站点或该域名的 [速率限制](#rate-limit) |
| 需要登录 | 配置 [Cookie](#credentials) |
| 年龄验证拦截 | 站点返回了年龄确认页; 在浏览器中完成年龄确认后, 把对应 Cookie 填入该站点的「Cookie」 |
| 站点未找到该内容 | HTTP 404; 检测入口不存在时检查「自定义域名」 |
| 站点服务器错误 / 空响应 | 站点自身故障, 稍后重试 |
| 上游接口报错 | 接口返回错误, theporndb 多为 API Token 无效 |
| 来源不可用 | 插件配置与插件版本不匹配, 检查插件配置 |

!!! note "可访问不等于刮削成功"
    检测只确认入口能否访问. javdb 的首页公开, 未配置 Cookie 时同样显示「可访问」; 无码影片能否获取以刮削结果为准. official 只代表所请求的那一个制作商官网.
