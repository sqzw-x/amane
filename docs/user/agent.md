# 使用 AI 智能体

Amane 可以把它的能力开放给你自己的 AI 智能体 — [Claude Code](https://claude.com/claude-code)、Codex 之类的命令行工具. 之后你可以直接用自然语言让它查询片库、批量整理、发起刮削、排查失败任务.

智能体不是通过界面操作 Amane, 而是调用实例提供的命令行工具. 数据始终留在你自己的机器上.

## 前提

智能体需要能执行命令, 并且能访问 Amane 的地址. 云端沙箱里的智能体访问不到你本机的实例.

## 开始

1. **打开「用户手册」页的「配置外部 Agent」一节**, 复制页面上给出的那段话.
2. **把那段话发给智能体**, 它会照其中的地址与步骤接入.
3. **按它的提问回答**: 装到哪里、要不要加入 `PATH`、跨机时粘贴一次访问令牌、Skill 装到哪个目录.

之后就不用再管了. 智能体会自己下载工具、完成鉴权、装好说明书.

## 它会问你什么

| 提问 | 说明 |
|------|------|
| 命令行工具装到哪里 | 建议放在已在 `PATH` 上的目录; 否则之后都用完整路径调用 |
| 是否修改 `PATH` | 它会先把要追加的那一行给你看, 同意后才写 |
| 访问令牌 | 只有实例不在本机时才需要. 令牌来自桌面菜单「复制 API Token」或服务端启动日志, 由你自己粘贴给命令行工具, 不经过对话 |
| Skill 装到哪个目录 | 各家智能体的约定不同, 它不确定时会问你 |

## 你的令牌

令牌等同于本机的完整控制权. 它只保存在本机的配置文件里 (权限 600), 命令行工具自己读取, 因此不会出现在对话内容中.

不要把令牌贴进聊天窗口. 需要重新登录时, 在自己的终端里运行 `amane login`, 按提示粘贴.

## 安全边界

- 服务端不设「二次确认」: 智能体是否先征求你的同意, 取决于它遵守 Skill 里的说明. 也就是说这是**文本约束, 没有强制力** — 务必使用指令遵循较好的模型, 否则可能误操作导致数据丢失. 请留意它对删除、合并、批量修改这类操作的描述.
- 每次调用都会记进日志, 事后可以在日志页查到做了什么.

## 常见问题

**它说连不上实例** — 确认 Amane 正在运行, 地址与端口正确.

**它说鉴权失败** — 在自己的终端运行 `amane login`, 粘贴桌面菜单或启动日志里的令牌.

**macOS 提示无法验证开发者** — 工具是用浏览器下载的. 让智能体改用 `curl` 重新下载.

**它说版本不一致** — 运行 `amane upgrade` 更新工具, 或重跑 `amane skill install` 更新说明书.

**它读不到日志** — 只有智能体与实例在同一台机器上时才能直接读文件. 跨机时它会改用接口导出的记录.
